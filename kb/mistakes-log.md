If it is, the work arrived, whatever the route. **Two rules follow.** (1) *A negative test must use the project's real workflow, not a synthetic case chosen because the check handles it.* Row 20 established that a guard is not a guard until seen to FAIL on the input that prompted it; this adds that it is not trustworthy until seen to PASS on the ordinary case it will meet every day. (2) *Prefer the check that reads the artefact over the check that reads the metadata.* Files are what the author can act on, and the FAIL message now names files rather than SHAs for the same reason. **Seen 2nd the same hour, third route:** the content test itself then flagged `data/health-log.jsonl`, a machine-appended record a CI job commits to main continuously, so it diverges from every branch by design and the check would have cried wolf on essentially every completed branch again. Machine records are now excluded and the rule is stated in the file: **compare what a PERSON wrote.** Note how both were found — by running the check on the real branches after merging it, not by its own tests. A guard needs a live shakedown against the last few weeks of real branches before it is trusted, because the cases that break it are the ordinary ones its author did not think to simulate |
