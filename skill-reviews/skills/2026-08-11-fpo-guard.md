# Skills review — the FPO guard, 2026-08-11

## Verdict

**Green.** The repo's most-filed open defect finally has a mechanical guard, on its fifth filing.
The guard's first act was to prove that every previous count of the defect — four filings, the
handover, and the status board — was **understated**, because all of them measured the wrong thing.

## Pre-flight

`node scripts/system-health.mjs` — **0 failing**, 38 warning, 70 ok. Working tree clean.

## What it guards

`Placeholder.astro` renders a real `<img>` when given `src`, and otherwise an FPO well whose
**visible text is the art direction**: the label, the description sentence, and the dimension string.
An unfilled slot publishes `Image placeholder` and `4:5 · warm tone · ~1000×1250` as body copy to
readers and crawlers.

Filed **four times** without ever being caught by the build — 28 Jul (`white-card-wa`), 29 Jul (the
system audit, naming 11 pages at once), 1 Aug (`white-card-nsw`), 4 Aug (`white-card-act`). Nothing
could see it: it is valid markup, the alt-text rule does not reach a `<div>`, and every other check
reads structure rather than what a reader sees.

`FPO_BUDGET` in `guardrails.ts`, as check 7a2.

## The finding, which is bigger than the guard

**Detecting structurally rather than textually changed the answer.** The guard keys on `.ph-in`, the
FPO branch's own wrapper, because `label` is a **prop** — a text match misses any well that
overrides it.

`Credentials.astro` overrides it twice:

```
:156  <Placeholder ratio="r45" label="Logo"     desc={org.name} spec="4:5 · supplied by the RTO" />
:236  <Placeholder ratio="r45" label="Portrait" desc={p.name}   spec="4:5 · grayscale · FPO" />
```

So every count ever published for this defect was low:

| | Text match (`Image placeholder`) | Structural (`.ph-in`) |
|---|---|---|
| `/white-card-wa` | **0** | **1** |
| `/white-card-tas` | **0** | **1** |
| `/white-card-act` | 2 | **3** |
| `/white-card-nsw` | 2 | **3** |
| `/white-card-qld` | 2 | **3** |
| Indexable pages affected | 11 | **13** |
| Wells on indexable pages | ~14 | **20** |

**`/white-card-wa` and `/white-card-tas` were reported as having no placeholders at all**, and the
status board rated both "images OK" — while each shipped an RTO partner logo well. That is not a new
defect: it is the already-filed *"Blue Dog, AlertForce and Upskill each need a supplied logo asset
plus a `logo:` line in their partner record"* item, which the FPO counting had simply never been able
to see. Six of the 20 wells are logos and portraits, which is a different ask from page art and is
worth separating when the images are commissioned.

`scripts/page-status.mjs` was corrected to the same detector, so the board no longer undercounts
(12 → 14, which is 13 indexable plus the noindexed NSW page that sits in the planned inventory).

## Design decisions

- **Ratcheted, not a flat FAIL.** 13 indexable pages breach today and the fix is to generate images,
  which no session can do alone. A flat FAIL would redden every build over work blocked on a person
  — the same reasoning as `BANNED_CTA_BUDGET`, `INLINE_STYLE_BUDGET` and `CPL_BUDGET`, and the
  fourth time this shape has been the right answer.
- **Noindex pages exempt, deliberately.** A page held out of the index is unfinished on purpose;
  failing it would punish the state the repo uses to stage work. `/owner-builder-nsw-course`, its
  `-w` variant and `/styleguide` carry 16 wells between them and are correctly silent.
- **Structural detection.** See above — this is the decision that produced the finding.
- **Budget derived programmatically from `dist/`, not typed.** The first attempt *was* typed, from
  the text grep, and the guard rejected it on five pages. That is the CPL budget's lesson
  (10 Aug: a table typed from a truncated terminal listed 7 pages when the truth was 11) arriving
  again from a different direction: **a budget table derived by hand from a weaker measurement than
  the check's own is wrong by construction.**

## What worked

Choosing the detector on a property of the component rather than on its output text. The reason was
defensive — `label` is a prop, so a text match is fragile — and it turned out to be the whole
finding. Had the guard matched text, it would have been built, gone green, and quietly certified two
pages as clean that were not.

## What didn't

The first budget table was hand-typed from the text grep and was wrong on five pages, which the
guard caught immediately. That is the second time in two days a budget table has been derived from a
weaker source than the check itself. The rule is now explicit in both files' comments: **derive the
table with the check's own detector, programmatically.**

## Demand list
Tag every item: [skills] | [design] | [facts] | [build]

- [build] **20 FPO wells on 13 indexable pages**, tracked line-by-line in `FPO_BUDGET`
  (`guardrails.ts`). Lower each entry as a page is filled; the build fails if a count drops without
  the budget following. Prompts exist for most in
  `handover/HANDOVER-image-prompts-2026-08-02.md` and the two 06-image-prompts artefacts.
- [build] **Six of those 20 are RTO logos and expert portraits, not page art** — `Credentials.astro`
  renders them via `label="Logo"` / `label="Portrait"`. They need supplied brand assets and a
  `logo:` line in each partner record, which is a procurement task rather than an image-generation
  one. Already filed against the partner records; re-stated here because the FPO count now includes
  them for the first time.
- [skills] **No check asserts that a `Placeholder` given a `src` also has usable `alt`.** The
  component falls back to `alt={alt ?? desc}`, so a filled slot with no `alt` silently publishes its
  art-direction sentence as alt text. The >= 80-char alt rule catches length, not provenance. Worth
  a guard when the images land, which is exactly when it would bite.
